# R2m 主人公離脱中の味方局所防衛レビュー

## 判定範囲

R2l後の小単位として、主人公P1が自陣の防衛室を離れている間に、味方支援型P2/P3が自分の現在室にいる敵を物理的に防衛できる境界を確認した。対象は、同じ広場または同じ城内ルームで、実際の位置と見通しが成立する敵だけである。

同室の敵へは、支援型が通常の固定小数点移動で近づき、ダッシュ可能な距離に入ると既存の物理ダッシュと人物接触へ進む。敵が倒れるか現在室から離れた後は、支援型の既存の補給運搬ループへ戻る。

## 実装

- `supportThreatAtActor` が、支援型・生存・保護解除済み・敵対・同じ物理空間・見通し成立の条件で、距離と人物IDの安定順に対象を選ぶ。
- `processSupportDefense` が対象へ歩行し、近距離では共通の `startActorDash` を開始する。局所防衛対象がなければ既存の `processCarrierAI` を呼ぶ。
- 防衛タスクは対象人物IDだけを保持し、別室・別城・閉門越しの authored route を作らない。将来の正式な味方命令とは分離する。
- 既存の敵侵入兵・内部兵が使うダッシュ開始関数は `startActorDash` へ一般化したが、攻撃距離・速度・接触・損傷の数値は変更していない。

## 検査

`tests/scenarios/r2m-support-defense.test.ts` で次を確認した。

1. P1が敵城側にいる状態でも、同じプレイヤー城内のP2が侵入敵へ物理移動・ダッシュ・接触し、敵を撃破する。
2. 別室の敵は隠れた防衛対象にせず、P2は部屋を越えて移動しない。敵が同室へ入って撃破された後、P2は補給運搬へ戻る。

局所シナリオは 2/2 通過した。全Node回帰、型検査、資料検査、製品ビルドの最終結果は `docs/TEST_REPORT.md` のR2m欄に記録する。

## 今回の非対象

正式な味方命令、P1が不在でない場合の優先順位、別室への救援経路、閉門・跨城の自動経路、4役割30人全員の通常行動、標準条件での一戦勝利、結果・得点・ランキング、iPhone実機・試遊は完成扱いにしない。支援型の局所防衛を確認したことは、味方AI全体や通常戦全体の完成を意味しない。
