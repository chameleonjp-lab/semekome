第5版では採用した一組の配置を先に成立させる。旧案の3配置制作を先に進めず、広場戦とランキングを初期公開の必須条件として残す。

検査の実施範囲と残件は [TEST_REPORT.md](TEST_REPORT.md)、今回の判断は [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md) に記録する。`ACCEPTANCE_TESTS.json` は計画全体の検査仕様であり、ファイルが存在するだけで全検査の実行済みを意味しない。

PR #14は、設備修理を外装修理と分離したR3の小さな単位である。自陣の修理室で所持中のケースを1個予約し、砲台または補給口を対象に120更新（2秒）作業を行う。完了時に設備耐久を復旧し、外装修理予算は消費しない。移動・ダッシュ・被弾・死亡・世代変更・修理室からの離脱ではケースを戻す。自動復旧期限と同じ更新は手動完了を先に判定し、二重復旧・二重消費を防ぐ。8種ケースの特殊効果、補給生成・配送の共通ルール接続、実広場、通常戦の勝敗、観戦・結果・ランキングは未完了である。

PR #15は、R3の補給接続を一度に全面統合せず、生成物の共通オブジェクト投影と砲台待ち列投入の境界を追加した。操作確認版で生成した4種ケースへ共通カタログの `weaponId` と生成元グループを保持し、受渡し後の装填時には同じケースを共通 `enqueue_object` へ渡して、所有者・世代・陣営・待ち列容量・待ち列番号を検証する。固定座標、受渡し枠、配送AI、経路・部位の捕捉、飛翔・迎撃・消費は物理側の責任範囲に残し、共通側の時計・乱数・履歴は物理状態へコピーしない。共通遷移が拒否された場合は受渡し枠とケース所在を元に戻す。8種ケースの特殊効果、効果の停止時計・速度係数、補給生成そのものの共通実行、実広場、通常戦の勝敗、観戦・結果・ランキングは未完了である。

PR #16は、PR #15の物理発射境界へ共通カタログと同じ8種のケース定義を保持し、着弾後の3効果を物理状態へ接続した。分割弾は中点通過後の接触判定を先に行い、飛行物体上限に空きがある場合だけ同じ由来・経路・目標を持つ子弾3個へ置き換える。補給妨害は対象車両の補給生成だけを360更新止め、240更新の免疫を別時計で保持する。通路妨害は対象車両の正面入口に半径1床の一つのゾーンを置き、そこにいる敵味方の歩行速度へ0.65を掛ける。初期R2aの標準4種補給袋は変えず、共通側からの自動生成・配送AI・実広場・通常戦終局は未完了のまま残す。

PR #17は、PR #16まで物理側だけで決めていた補給ケースの生成・配送開始を、共通 `WorldState` の遷移で再検証する境界を追加した。`spawn_supply` は補給口の陣営・部屋・床セル、ケースのカタログID・重量・由来グループ、ケースIDの一意性を確認してから、物理側がバッグ・グループ・次回補給時刻を消費する。共通側の拒否では物理側の順序やケースを進めない。`reserve_delivery` は運搬手が所持するケースと自陣砲台を予約へ結びつけ、物理側の受渡し枠へ置く前に人物世代・所有・陣営・予約IDを共通側でも確認する。共通時計・乱数・履歴は物理状態へコピーしない。共通スケジュールの自動生成、配送AI、実広場、通常戦の終局、観戦・結果・ランキングは未完了である。

PR #18は、PR #17の配送予約を受渡し床の枠単位へ狭め、`targetStagingSlot` を共通予約に保持する。共通 `reserve_delivery` は同じ砲台・同じ枠の二重予約、authored floor の枠外指定を拒否し、物理運搬AIはケースを拾った後に空き枠を一つ確保してから砲台へ向かう。受渡しが成立すると枠へ置く前に予約を解放し、破棄・死亡・拒否では予約とケースの所在を戻す。既存の物理距離・見通し・枠占有、待ち列投入、共通時計の非コピーは維持する。共通スケジュールの自動生成、配送先の再選択、実広場、通常戦終局、観戦・結果・ランキングは未完了である。

PR #4の `src/simulation/battle.ts` は8武器のデータ読込、P1の検証済み操作命令、射手・設備・48更新共有枠、区間迎撃、分裂、同更新開始時の外装への着弾、補給妨害時計、入口減速の係数、4役割の判断を保持する。補給生成と実移動はこの入口へ接続しておらず、検査では現物と人物位置を明示配置している。

PR #5の `src/simulation/physical-battle.ts` は操作確認画面から呼ぶ。名前・カウントダウン・実移動・4種の補給と現物の所有権を検査する。8武器の共通ルールとは別の状態・命令・座標単位であり、相互に状態を渡したり、同じ試合へ両方の更新関数を重ねて呼ばない。公開APIの `createBattle` / `stepBattle` はPR #4の契約を維持し、操作確認用の公開入口は `physicalBattle` 名前空間に分ける。

PR #6は `src/simulation/r2b-bridge.ts` を追加した。物理側の固定座標・試合・更新・生存世代・経路・床見通しを検証してから、共通ルールの核接触入力へ変換する。広場側は護衛の所在と生存世代をスナップショットで照合し、全護衛が倒れている場合だけ世代付き通過権と `entry` 入力を準備する。どちらも時計を進めず、呼出側が同じ更新で一度だけ `stepWorld` へ渡す。これで核一撃と相互侵入の不正な直接入力を塞ぐ最初の接続を成立させたが、人物同士の被弾、実際の広場座標、補給・効果・敵判断の接続、5秒観戦画面は未実装である。

PR #7は `BattleIntent.bridge` と `prepareR2bWorldInput` を追加し、物理 `stepBattle` の一更新内で検証済みの核接触／広場入場を `stepWorld` へ一度だけ渡す。共通側の状態とイベントは取り込むが、時計・乱数・`lastStep`・イベント履歴は物理側で所有して最後に一度だけ更新する。核接触で終局した場合の終局イベント重複も抑止する。実広場の連続座標、人物同士の被弾・突進、補給効果・敵判断、観戦画面は残件である。

PR #8は `actor_contact` 証跡を追加し、同じ城の室でダッシュが最初に人物へ接触した場合だけ、共通 `stepWorld` へ対象への1損傷を渡す。対象の36更新被弾無敵、選択中ケース一個の落下、死亡時の既存荷物処理を共通側で確定し、物理側では0.6床の押し戻しとケース位置を固定座標へ投影する。人物接触の橋渡しは補給装填・発射前に行い、時計は物理側だけが一度進める。12更新の突進移動・54更新待ち、設備接触、内部兵AI、実広場座標、補給効果・敵判断、観戦画面は残件である。

PR #9は `BattleIntent.dash`、突進の残り更新数・再使用可能時刻、1.2床／12更新の固定移動を物理状態へ追加した。各更新の掃引は歩行と同じ人物半径・壁・門・設備判定を通り、最初の敵人物で停止して `actor_contact` を、核室到達で `core_contact` を自動生成する。証跡は既存の橋渡しへ同じ更新で一度だけ渡し、損傷・無敵・押し戻し・終局は共通側の権威を保つ。設備への10損傷、内部兵AI、実広場座標、画面の突進操作、補給効果・敵判断、観戦画面は残件である。

PR #10はPR #9の設備停止境界を、砲台・補給口の物理状態へ接続した。敵設備に突進が最初に接触した場合だけ、`dash_equipment_damage`（10）を耐久60から減算し、0になった設備を480更新停止する。停止中は砲台の装填・発射と補給口の生成を止め、待ち列・補給時計は保持する。停止期限の次の更新で耐久を60へ戻し、設備復旧イベントを一度だけ記録する。味方設備は当たり判定で突進を止めるが損傷させない。設備への損傷・復旧は物理状態の責任範囲に留め、人物損傷・終局の既存R2b橋渡し境界は変更しない。内部兵AI、実広場の連続座標、画面の突進操作、補給効果・敵判断、観戦画面は残件である。

PR #11は物理側に内部兵専用の `enemyDecisions` と36更新周期を追加した。E25〜E27は中央通路へ広場警備、E29〜E30は同じ中央通路へ限定侵入、その他は担当室の巡回を `move_goal` として固定経路で歩く。同じ城・室の侵入者には `defend`、体力2以下では `retreat` を選び、防衛時は見通しと距離を確認してAI突進を既存の人物接触橋渡しへ渡す。公開P1の突進・明示証跡と同じ更新ではNPC移動を抑え、公開証跡を古くしない。共通ルール側の敵判断はPR #12へ引き継ぎ、実広場座標、修理・補給効果、画面の突進操作、観戦画面は残件である。

PR #12は、物理側の固定座標から共通 `chooseEnemyIntent` と同じ優先順位を使う観測を作り、射手4人・射手護衛4人・弾薬運搬8人・内部兵14人の30人全員へ36更新周期の `enemyDecisions` を保持する。防衛・退避は既存の壁・門・床見通し・人物半径を検査する固定移動へ渡し、射手の砲台操作と運搬手の現物受渡しは既存の個別検証を通す。共通の意図をコピーしても座標・損傷・荷物状態を直接変更せず、公開P1の突進または橋渡し証跡がある更新ではNPC移動を抑える。修理・補給効果、実広場の連続座標、門を越えた相互侵入、観戦・結果・ランキング画面は残件である。

PR #13は、R3の最初の修理単位として、物理操作確認版の修理室へ外装修理を接続した。P1が自陣の修理室で所持中のケースを1個選ぶと、対象部位（明示指定、または損傷率最大・同率は部位番号順）を開始時に固定し、ケースを `repair` 予約へ移す。90更新の作業中は移動・ダッシュ・被弾・死亡で中断し、予約とケースを戻して回復予算を消費しない。完了時だけ対象の未破壊部位を最大12回復し、車両ごとの累計96予算から実際の回復量を消費し、ケースを一つ消費する。同じ部位の同時予約、破壊済み・全快部位、予算切れは受け付けない。設備修理、8種ケースの特殊効果、補給生成・配送の共通ルール接続、実広場の連続座標、門を越えた相互侵入、観戦・結果・ランキングは残件である。

R2bでは[接続契約](RULE_ENGINE.md)に従って両処理を統合し、突進の最初の接触を検査する。広場横断には人物と生存世代・試合・出撃回を記録し、途中合流者へ無条件の通行権を渡さない。R2aの画面では広場侵入や通常戦の勝敗を未実装として明示する。共通ルール側の敵の移動目標・自衛・退避は意図だけであり、操作確認版の簡易物流AIとは未接続。分裂・妨害・減速と実際の補給・歩行をつなぐ検査も残す。

R2b着手時には、人物の所属陣営と現在いる城、ケースの生成元と物理的な所在を分離して全操作を接続し直す。R2aの「所属する城内だけを操作可能」という制限を外すだけで相互侵入を実装済みにしない。通過室履歴も出撃単位で必要な証拠を保ちつつ圧縮し、往復のたびに無制限に増える形を残さない。
