# 実装の進捗

基準：第5版 / `semekome-prototype-0.4-facing-castles`。

|段階|今回の扱い|完成条件|
|---|---|---|
|R1 設計と基礎|実装・自動検査済み。Draft PRで確認|第5版資料同期、7部位・7門・核、30人・個別復活・実床の接続・所在・時計・仮画面|
|R2 一戦を通す|未着手|名前登録とカウントダウン、移動、現物運搬、砲台、迎撃、広場突破と侵入、コア命中までの一戦|
|R3 車内の判断|未着手|補給配分、受渡し、待ち列、修理、設備妨害|
|R4 仲間と戦術|未着手|4役割の仕事と警戒、味方命令、残りのケース|
|R5 製品として整える|未着手|練習、結果・スコア詳細・共有・上位10位、再戦|
|R6 公開前の確認|未着手|全要件、実機、負荷、連続再戦、外部接続、素材・名称の確認|

第5版では採用した一組の配置を先に成立させる。旧案の3配置制作を先に進めず、広場戦とランキングを初期公開の必須条件として残す。

検査の実施範囲と残件は [TEST_REPORT.md](TEST_REPORT.md)、今回の判断は [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md) に記録する。`ACCEPTANCE_TESTS.json` は計画全体の検査仕様であり、ファイルが存在するだけで全検査の実行済みを意味しない。

次のR2では、今回の内部イベントをプレイヤーが直接送れる仕組みにせず、実移動・最初の接触・現物の所有権を検査する処理から呼び出す。広場横断には人物と生存世代・試合・出撃回を記録し、途中合流者へ無条件の通行権を渡さない。
