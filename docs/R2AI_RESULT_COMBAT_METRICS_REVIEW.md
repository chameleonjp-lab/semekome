# R2ai：終局の人物集計と結果詳細の操作

## 対象と判断

PR #70（R2ah）取り込み後のmainを基準に、敵討伐延べ回数、一度でも倒した敵の人数、主人公P1の死亡回数を結果記録へ保存し画面へ表示する。敵は固定名簿30人、復活後の同じ敵は延べ回数だけを増やす。味方P2/P3による討伐も含めた味方全体の記録であり、P1個人の撃破数ではない。

`deathCount` は復活後も維持される累積値なので、件数上限で古いイベントが消えても集計は欠けない。余分なactor、別名のactor、名簿IDと一致しないactor、味方actorは敵集計へ入れない。P1の死亡回数は味方の死亡と合算しない。敵30人・1,200 tick復活、P1 300 tick観戦、7外装・7門・コア勝敗は変更しない。

## 記録と操作

終局時の同じpayloadに集計を保存する。開始記録、補給配列、結果payload、集計をコピー・固定し、呼出し元や返却値の変更で確定記録が変わらないようにする。再読込でも固定する。旧結果に集計がなければ欠損を維持する。browserの保存値自体を改変できない保証や外部ランキングの証明としては扱わない。

結果詳細のみをスクロールさせ、再戦・ホームのボタンは画面内に残す。終局の最後の描画後、戦闘入力とAbortControllerを解放してから結果DOMへ置き換える。再戦・ホームのリスナーは結果側で追加する。次の試合は新規ID・初期集計0となる。

## 独立レビュー

実装を6.1Sol Max、独立読み取りを6.1Sol Extra Highへ分けた。独立レビューは固定名簿、再討伐、味方討伐とP1死亡の区別、短いログ、終局投影、旧記録、得点・外部接続の境界を確認した。

- 結果のネストした集計が返却値から変更でき、メモリと保存値が食い違う指摘：コピーとfreeze、開始・結果・再読込の書換え拒否検査を追加して修正した。
- 無効化した旧ダッシュリスナーが結果詳細のSpaceを阻止する指摘：終局時のdisposeを追加し、SpaceのdefaultPrevented・実ページ送り・Tab順のbrowser検査を追加した。

再レビューで追加の重大・中程度の問題はなかった。Nodeスタブでも二重dispose、結果詳細のSpace非阻止、次戦だけの入力発火を確認した。静的レビューとNode検査はブラウザーやiPhone実機での合格へ読み替えない。

## 検査範囲と残件

集計単体は実接触・復活・再討伐・味方討伐・P1死亡・イベント上限・新規試合を通す。保存単体は入力コピー、返却値の固定、再読込、同じ結果の再処理、旧欠損を検査する。browserは通常初期配置の実終局と、累積値を与えて時間切れを短縮した表示fixtureを分ける。後者では勝敗やendedを直接与えず、本来の更新で時間切れを確定する。

短画面・横画面・200%文字・Space・Tab・再戦・ホームはChromium/WebKitで検査した。[Quality #452](https://github.com/chameleonjp-lab/semekome/actions/runs/36835325866) はコード `406c11f` のNode318/318、資料57/57、型・製品ビルド、browser58/58（各29件）を通過した。ローカルブラウザー取得は失敗し、Qualityのrun-browserで実行した。確定した実行範囲は [検査記録](TEST_REPORT.md) を参照する。iPhone実機・試遊は未確認。

正式な得点式、共有側の登録値、開始・結果の外部送信、上位10位、共有・実験場リンクは未完了。通常画面での複数回走破、実戦バランス、正式な味方命令、敵味方の通常行動と相互侵入も別対応とする。mainへの直接変更、マージ、公開は行わない。
