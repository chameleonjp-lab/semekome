# R2d 主人公の通常入力と広場境界の独立レビュー

対象はPR #37取り込み後の主人公通常入力の小単位である。初期位置のP1が公開 `direction` / `handle` だけで補給1回、砲台受渡し、正面通路、広場、敵城側境界まで進み、未撃破の世代付き警備が敵城側入口を止めること、広場HUDが警備状態を説明することを読み取りと回帰検査で確認した。通常戦の勝利、mainへの直接push、マージ、公開承認はこのレビューの範囲外である。

## 発見と確認

|観点|確認内容|結果|
|---|---|---|
|通常入力の境界|`tests/scenarios/r2d-player-plaza-route.test.ts` は公開P1入力で補給1回の取得・受渡しから正面通路を通って広場へ進む。敵城側では通常の held direction だけを送り、bridge入力や座標注入を使わない|確認済み。固定更新の経路テストが273件のNode回帰に含まれる|
|警備世代|テストfixtureはE25〜E27を出動集合として登録し、生存世代を保持する。境界到達時も少なくとも1世代が生存し、`enemyCrossings["P1:0"]` は許可されない|確認済み。`bridge:plaza_entry` は受理されない|
|HUDの表示根拠|`battle-hud.ts` は登録済みの `plazaGuardCandidates` を使い、死亡者を残数から除外する。未登録時は自城/広場の生存防衛者を操作ヒントとして表示し、権限を先取りしない|確認済み。出動前・残存3人・全撃破の3状態を回帰|
|fixtureの意味|敵AIの戦闘干渉を保護状態で切り離し、移動と越境境界だけを安定して測る。戦闘・広場戦術・勝敗を同時に完成扱いにしない|文書とテストの双方で明記|
|既存ライフサイクル|出動時点の世代、撃破後の通過権、復活世代、離脱・再侵入の本体処理はR2cの既存テストが担当する。今回のHUD/通常入力テストはその候補集合を読み取る|責任範囲の重複なし|

## 検査結果と残る境界

今回の範囲では重大な未解決所見はない。R2d局所回帰は7/7、全Node回帰は273/273、資料57/57、型検査、製品ビルド、差分空白検査を通過した。ブラウザ50件はChromium実行ファイル未取得とWebKit共有ライブラリ不足で起動できず、実装の失敗とは分離して記録する。

採用配置での主人公の運搬・迎撃・砲撃→7部位破壊→広場戦→7門→核接触→終局、味方命令、正式結果・得点・ランキング、iPhone実機・試遊、提出版の最終CIはこの単位の合格範囲に含めない。境界fixtureを通常戦全体の完成証拠へ読み替えない。
