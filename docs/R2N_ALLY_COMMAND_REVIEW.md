# R2n 味方支援型の守備・補給復帰命令レビュー

## 判定範囲

R2mの局所防衛を、P1が明示的にP2/P3へ出す2種類の命令として固定した。

- `hold`：対象の現在位置を保持し、同じ物理空間に見えている敵だけを既存の局所防衛へ渡す。
- `supply`：`hold` を解除し、既存の補給運搬AIへ戻す。

命令はP1の公開入力からだけ受け付け、対象は生存中のプレイヤー支援型P2/P3に限る。命令は対象の生存世代に束縛し、P2/P3が復活した場合は古い守備命令を引き継がない。P1/P2/P3の人物座標、別室への経路、敵の未観測情報を命令入力へ持ち込まない。

## 実装

- `BattleIntent.allyCommand` を追加し、`allyId` と `kind` 以外の識別子・座標を受け付けない。
- `BattleState.allyOrders` にP2/P3ごとの守備命令と対象世代・発行更新を保持する。
- 守備中はR2mの `processSupportDefense` を再利用し、脅威がない更新では移動計画を消して現在位置を保持する。
- `supply` は命令と旧経路を消去し、通常の補給運搬へ戻す。復活時は世代更新と同時に古い命令を消去する。
- 通常戦画面の「味方」からP2/P3ごとに守備指示・補給復帰を一更新の公開入力として送る。

## 検査

`tests/scenarios/r2n-ally-commands.test.ts` で次を確認した。

1. P2への `hold` が補給移動を止め、`supply` 後に補給ループへ戻る。
2. 守備命令中のP2が同室の侵入敵へ既存の物理ダッシュ接触を行い、別室の敵へ救援経路を作らない。
3. P2/P3以外の対象を拒否し、P2の死亡・復活後へ古い守備命令を持ち越さない。

ブラウザでは、味方命令の開閉、P2の守備指示、補給復帰の表示と状態属性を確認する。iPhone実機・試遊は別工程である。

## 今回の非対象

P1への命令、任意地点・任意人物の指定、別室救援、別城・広場への自動経路、複数命令の優先順位、敵味方30人全員の行動、標準一戦の勝利、正式結果・得点・ランキング、iPhone実機・試遊は完成扱いにしない。R2nは正式な味方命令の最小入力境界であり、味方AI全体の完成を意味しない。
