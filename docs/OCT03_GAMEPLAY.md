# 2026-10-03 操作・戦闘の更新

## 利用者指定

現行第5版を基準に、移動高速化、敵の自動作戦、進行方向への射撃、全員の自動弾回収（最大5個）、弾回収・砲撃中心の味方指示と2人の引率、出口案内、4方向の人物表示、床弾の拡大、連打時の拡大防止へ変更する。今回の指定は、旧版の2枠・重量3、手動拾得、近接攻撃中心、敵の作戦をプレイヤーが選ぶ画面より優先する。

敵30人、各人の討伐20秒後復活、主人公5秒観戦復活、外装7部位と7門、正規通路から核への有効な一撃、自陣左・敵陣右、相互侵入を維持する。ランキング停止は別の変更であり、この操作改修によって再開しない。

## 実装する調整値・解釈

- 全員の歩行は毎秒6床単位（従来3の2倍）。画面の大きさに依存しない。移動専用突進は12更新で2.4床単位（歩行の2倍速）、無敵なし、壁・門・最初の人物や設備で停止する
- 床のケースは接近時に自動取得、重量にかかわらず5個まで。ケースの所有・消費・落下・砲台受渡しは既存の現物管理を維持。落下直後30更新は自動再取得を待ち、置く操作が即座に取り消されないようにする
- 人物射撃は装備した短射程の武器。運搬ケースは従来どおり砲撃・迎撃・修理に使う。ケースを持たない警備員や復活直後の人物が戦闘不能になることを避ける補足解釈
- 射撃は8床単位、18更新の間隔、人物損傷2・設備損傷10、表示8更新の初期調整値。壁・閉門・最初の敵で止まり、外装への人物射撃では外装を壊さない。核への射撃は全7門を正規通路で越えた核室からの有効な一撃だけを認める
- 「射撃」またはXで現在の進行方向、停止時は最後の進行方向へ攻撃（初期は味方が右・敵が左）。NPCも人物への攻撃に射撃を使う。通常画面の突進は接触時に止まる移動専用で、人物・設備・核への損傷を与えない。旧攻撃型の突進APIは明示的な内部互換テストにだけ残し、通常の画面入力とAIから呼ばない
- 基本命令は弾回収・運搬と砲撃。弾回収は明示的なcollect命令で、整備型や迎撃型を選んでも通常業務への取消しに読み替えず、現物の回収・配送を優先する。敵陣・広場にいる味方への弾回収・砲撃指示は、近くの敵を追い続けるより先に自陣への帰還を開始する。「2人を引率する」でP2/P3へ同行命令を順に届ける。死亡・世代変更・停止時の未送信命令破棄を維持。同行中は班長と同室かつ双方から8床以内の見える敵だけを移動・射撃で援護し、班長が離れたら即座に合流を優先する
- 敵の作戦選択欄をなくし、通常戦は標準AIが戦況を見て判断する。難易度は引き続き選択できる
- 4方向は既存の役割別右向き画像・左反転と、コード描画の正面・背面を使う。斜め移動は射撃も斜め方向を維持し、4面表示は横方向を優先する補足解釈。新たな外部素材・有料生成は使わない
- 床弾を最小18pxと目立つ足元の輪郭で表示。実際の入口を強調し、自陣・広場・敵陣の方向案内を表示
- ライブ操作部分だけでtouch-actionとdouble-click抑止を適用。viewportのズーム上限やuser-scalable=noは使わず、説明文のスクロール・ピンチ拡大を残す

上記の速度・射程・間隔・損傷はユーザーが数値指定したものではない。試遊による調整は残る。

- 5個を持った専任射手は、その現物を砲台の検証済み待ち列へ投入して空きを作る。護衛・内部兵も自陣で回収した弾は正規の配送へ回すが、専任射手以外へ砲撃権限を与えない。生成元グループ上限による弾の抱え込み停止を回帰検査する

## 互換性と検証

ルール版は `semekome-prototype-0.5-directional-cargo5`、物理リプレイ版は2へ更新した。旧記録を新しい速度・所持数・射撃ルールで黙って再生しない。得点式自体は変更せず、ランキングの通信停止は維持する。


- 新しい物理テストで速度、5個自動取得、射撃方向・障害物・敵味方、核の正規経路・守備者遮蔽・同時命中引き分けを検査する
- 同行は2人とも自陣から広場、敵陣、再び自陣へ実入口を通って移動することを検査。閉門の通過履歴は増えず、停止・死亡・復活世代で命令が漏れないことを別に検査
- 表示テストで6役割×4方向、上下反転しない描画、床弾寸法、左右の入口、射撃表示の秘匿を検査する
- `tests/browser/oct03-controls.spec.ts` は敵選択欄なし・5枠・射撃・連打・2人への3命令を通常画面で検査し、成功時にもスクリーンショットを添付する。同ファイルの描画専用fixtureは実画像の読み込みを確認した6役割×4方向の一覧を撮影する。戦闘の勝利検査とは別に扱う
- 過去のブラウザ検査は、新しい所持枠・自動取得・速度・命令に対応させる。旧仕様を守るためだけの期待値は使わない
- ローカルブラウザは起動時のsocket権限制限が既に確認されているため実行していない。ブラウザCI、iPhone実機、実戦の難度と体感、初心者試遊の合格とは区別する

型・Node・資料・ビルドの確定結果は、この変更を提出する際の検査報告を参照する。未実施を合格としない。
