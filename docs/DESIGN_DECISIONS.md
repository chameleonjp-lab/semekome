# セメコメ R1の実装判断

基準はPR #2取り込み後の `f222307069e270818223daa2a464530a8fae3a4b` と第5版の追補文書。ユーザーの「計画書に従い実装開始」と添付「実装組織図」に基づき、今回の変更単位を計画16章のR1とした。

## 今回完成させる範囲

第5版に計画本文・要件・検査計画・配置・名簿を同期し、両城の7部位・7門・核、敵30人、個別復活、部屋と実床の接続、物体の所在、戦闘時計と停止処理の基礎を実装する。画面はR1の配置確認用とし、通常戦が遊べるという表示をしない。

通常移動と突進の連続当たり判定、現物の運搬と装填、砲撃・迎撃、敵の仕事、広場突破を含む一戦の成立はR2で扱う。基礎モデルにある内部イベントを、そのまま画面の操作や信頼できない外部入力へ接続しない。

## 配置の基準

自陣は左で正面が右、敵陣は右で正面が左。砲台A/Bは前方、C/Dは後方。敵陣の地形を左右反転しても、部屋名・操作・世界状態は反転共有しない。復活室は中央通路の後方に置き、さらに後方へ7門と核を補う。

添付図の採用は壁厚や難易度の承認ではない。今回定めた床座標と通路は補足案である。元リポジトリの縮小プレビュー画像には破損があるため、`approved/ADOPTION_RECORD.json` に検査結果を記録し、正常な原本が保存されていると扱わない。採用方針の本文に従って補足図と配置を整合させる。

## 描画と時計

ルールはTypeScriptで表示から切り離す。仮画面はブラウザ標準のSVGを使い、同じ配置データから正立した文字と部屋を描く。R1の仮図に戦闘エンジンの実装済み機能を仮装しない。Phaserは計画上の提案であり、R2の動く戦闘表示を作る時点で必要性と版を確認する。

TypeScript 5.9.3、Vite 8.3.0、Node.js 24を使う。依存関係はlockファイルで固定する。Phaser公式の [Vite/TypeScriptテンプレート](https://github.com/phaserjs/template-vite-ts/blob/main/package.json) は着手時に再確認した。テンプレートそのもののコピーや外部素材の転用は行っていない。

配置を確認する場所の変更は、カメラだけを切り替える。人物の現在地や試合を変える処理にはしない。仮画面では戦闘時計を進めず、基礎モデルの復活時計は自動検査で確認する。

R1の `Point`・人物位置・床上物体位置は配置とイベント検査用のセル座標とする。床BFSの合格を、人物半径・連続移動・突進の当たり判定の合格にしない。計画13.2の「1床単位＝1000整数」はR2で実装し、セル座標と移動用整数座標を別型に分けて明示変換する。R1の記録を移動座標へ暗黙再生しない。`125-x` はセル番号の反転であり、連続座標ではセル中心と矩形境界の原点を改めて定義する。この段階分けはAstra Highの設計再確認に基づく。
