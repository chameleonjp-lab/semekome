## PR #16：8種ケースの物理効果を砲撃・補給・歩行へ接続（2026-09-14）

PR #15の共通オブジェクト投影と待ち列投入に続くR3の次の小単位として、物理砲撃の着弾後にケース効果を適用する境界を追加した。`cases.ts` は共通カタログと同じ8種のID・重量・損傷・速度・迎撃耐久を持ち、初期R2aの補給袋（標準3・重量2・防護2・高速1）は変更しない。特殊ケースは選択済みの補給構成や明示テストからも同じ物理発射経路へ入れる。

分割弾は親が経路の中点を越えた後、接触を先に確定してから3個の子弾へ置き換える。子弾は同じ由来グループ・目標・経路を引き継ぐが再分割せず、間隔2、損傷4、迎撃耐久1で個別の所在を持つ。飛行物体上限96に3個分の空きがない場合は親を消費せず、一度だけ分割不成立を記録する。

補給妨害は着弾した対象車両の `supplyStops` だけを360更新停止し、終了後240更新の免疫中は延長しない。砲台、修理、設備停止時計とは別フィールドにして、停止中も待ち列・発射・修理を壊さない。通路妨害は対象車両の正面入口（セル中心、半径1床）へ一車両一つのゾーンを置き、敵味方を問わずその範囲の歩行速度へ0.65を掛け、重量3の0.85とは乗算する。期限切れは物理更新の開始時に破棄し、再命中は同じ対象車両のゾーンを置き換える。

このPRでは共通 `stepWorld` が物理発射を自動生成する境界、配送AI、広場の連続移動、跨城侵入、通常戦の終局、観戦・結果・ランキングは扱わない。外部から効果や損傷を入力する経路を作らず、物理飛行の着弾・迎撃・所在を権威とする。

## PR #15：補給ケースを共通オブジェクトへ投影し、待ち列投入を検証（2026-09-14）

PR #14の設備修理に続くR3の小さな単位として、補給生成物の共通投影と砲台待ち列投入の境界を選んだ。補給・配送・特殊効果を同じPRで全面接続すると、物理側の固定座標と共通側のセル座標、ケースの由来、受渡し枠、待ち列所有、飛翔効果の権威が一度に変わるためである。今回は物理ケースの生成状態を唯一の入力として、4種の操作確認ケースを共通カタログの同名 `weaponId`、`sourceTeam`、`originGroupId`、重量へ投影する。外部のIDや命中結果を投影値として受け付けない。

受渡し後の装填では、物理作業員が実ケースを拾った状態を一時的に共通 `enqueue_object` へ渡す。共通側は人物の生存世代・所有、陣営・砲台ID、待ち列容量・番号を再検証し、物理側はその結果を待ち列投影へ反映する。物理側の受渡し枠と貨物枠はこの検証が成功したときだけ確定し、共通遷移が拒否された場合は拾う前のスナップショットへ戻す。橋渡し用 `stepWorld` の時計・乱数・`lastStep`・履歴はコピーせず、物理 `stepBattle` が一更新の所有者であり続ける。

このPRで共通の由来と待ち列投入を検証できるようになるが、補給口が共通ルールからケースを自動生成すること、8種ケースの特殊効果を物理飛翔・歩行へ反映すること、配送AIの経路・実広場・通常戦の終局を実装したことを意味しない。次のR3単位では特殊効果または補給生成の共通実行境界を、物理所在の一意性を保ったまま追加する。

## PR #14：設備修理を外装修理から分離（2026-09-14）

PR #13の外装修理に続くR3の小さな単位として、設備修理を物理操作確認版へ追加する。砲台・補給口は人物や外装部位とは別の耐久を持つため、既存の外装修理タスクへ設備IDを混在させず、`equipmentTasks` と専用イベントを分けた。対象は作業員と同じ自陣の修理室にある自設備だけで、砲台または補給口を開始時に固定する。

設備修理はケース1個と120更新（2秒）を必要とし、完了時に設備耐久を手動復旧値（通常60）へ戻す。外装修理の累計予算96には加算しない。予約中のケースは共通 `reservations` の `repair` と `reserved-carried` で保持し、同じケースを発射・配送・別修理へ使えない。移動・ダッシュ・被弾・死亡・世代変更・修理室離脱は中断としてケースを戻す。

自動設備復旧は手動修理完了・中断の後に同じ更新で評価する。したがって手動完了が自動期限と重なる場合はケース1個の手動復旧だけを記録し、自動復旧イベントや二重消費を発生させない。手動作業中に先に自動復旧した場合は対象を無効として作業を取り消す。設備の停止理由（設備破壊と補給妨害）は混ぜず、手動修理では補給妨害時計を解除しない。

画面では修理室に設備対象の選択欄を追加したが、広場の戦い・敵陣侵入・核攻撃・通常戦の終局・結果とランキングは依然として未実装である。

## PR #13：外装修理の予約と物理反映（2026-09-14）

ケースは共通 `reservations` の `repair` と `reserved-carried` で一つの所在として保持し、発射・配送・別修理との二重利用を防ぐ。物理更新が時計を一度だけ所有する境界は変更せず、修理イベントは同じ `lastStep` に記録する。設備修理、8種ケースの特殊効果、共通ルールへの補給・配送接続、実広場、結果・ランキングは次の単位に残す。
