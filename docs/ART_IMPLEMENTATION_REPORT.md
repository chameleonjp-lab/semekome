# 表示素材の制作・実装記録

2026-09-27 JST。第5版のゲーム内表示を洗い出し、22画像を生成して個別素材化し、既存の操作確認版へ組み込んだ。

## 一覧と制作物

全表示要素は [VISUAL_ASSET_INVENTORY.md](VISUAL_ASSET_INVENTORY.md) に、導入前・今回接続・残件を分けて記録した。

|種類|個数|用途|
|---|---:|---|
|人物|6|主人公、補助員、敵の射手・護衛・運び手・内部兵|
|設備|5|砲台、補給口、核、門、修理|
|弾|8|標準、重量、防護、高速、分割、補給妨害、貫通、通路妨害|
|環境と効果|3|床、ステージ、衝突効果|

画像は機械工房のミニチュア風で一枚ずつ生成した。20点の背景透過を保ち、21点を256×256px、ホーム用ステージを1200×600pxのWebPへ変換した。実行用画像の合計は577,306 bytes（約0.58MB）。指示文は [ART_GENERATION_PROMPTS.json](ART_GENERATION_PROMPTS.json)、元画像と実行画像のハッシュ・寸法・透過・変換条件は [ART_ASSET_REGISTER.json](ART_ASSET_REGISTER.json) に記録する。

## 実装への接続

- ホームにステージ画像、素材図鑑に22点の画像と用途を追加。
- 配置確認の床、人物、砲台、補給口、7門と核へ画像を追加。敵砲台は左向き、文字は正立を保持。
- 操作画面は既存状態を読み、所在に応じた自城・敵城・広場、役割別人物、所持弾、設備の耐久と停止、門の開閉を描画。
- ケース8種は床・所持・待ち列・飛翔・補給選択・次の2個・作業ボタンへ同じ画像を対応付けた。
- 突進の残像、被弾、迎撃、着弾、修理などを既存の更新数とイベントから表示。迎撃地点は前回描画時の同経路2物体からの近似で、追跡できないときは効果を省略する。
- 画像読込と床をキャッシュし、画像が欠けてもCanvasの図形代替で操作を続けられる。描画はゲーム状態を変更しない。

変換は `node scripts/prepare-game-art.mjs /absolute/path/to/generated_images` で再実行できる。元PNGの名前とハッシュを台帳で検証する。sharpは制作時だけ必要で、ゲームの配布・ビルド依存には追加していない。

|実機|iPhone 17 Pro Safariでの実機確認は未実施|

ローカルのブラウザはPlaywrightから既存のChromium 153実行ファイルを使用した。WebKitを含む提出版の検査結果はDraft PRのQualityを参照する。生成画像の読み込み検査とゲームルールの検査は別であり、資料内の計画テスト135件を全実行済みとは扱わない。

初回Qualityではブラウザ23/24件が通過し、WebKitの小画面検査が開始準備中の一時停止画面で待機した。失敗時の画面とトレースを確認し、実時間のカウントダウンを待っていたレイアウト検査を、他の操作検査と同じ制御時計で進める方式へ修正した。ゲームの250ms超過時の停止や、離脱後の明示再開は保持する。床描画も元画像の縮小をセルごとに繰り返さず、床用サイズの画像を用意して再利用する。

日本語フォントを用いた390×844pxのブラウザ画面を保存した。[ホーム](art-preview/home.png) / [素材図鑑](art-preview/atlas.png) / [弾を持った操作画面](art-preview/battle.png)。フォントは撮影環境で読み込んだもので、アプリへ追加のフォント依存を組み込んでいない。
