自動画面検査では360×640、390×664、402×700、430×932、844×390を使用した。主要ボタン48px以上、画面外へのはみ出し、部屋選択・説明の表示、ルールダイアログの閉鎖とフォーカス復帰を確認した。配置画面は戦闘時計を進めない。

ローカル環境ではPlaywright標準ブラウザの取得に失敗したため、Chromium 143を指定して検査した。ローカルのWebKit検査は未実施。CIのブラウザ検査はローカル結果と分けて扱う。

## レビューで確認した修正点

コア命中を確定する内部イベントの境界、試合ID・生存世代を欠く入力の拒否、飛翔体と運搬物の参照、予約の解放、両城の待ち列の独立性を修正した。発射後の待ち列を詰め、同じ場所へ重複して入らないことも検査した。図の後方通路と実床を整合させ、両城の7門をそれぞれ一枚だけ閉じた14通りで核への道が遮断されることを検査した。

資料に残る旧設備数と未実装の表記、自陣人物の重なり、設備と復活床の表示、役割ごとの図形識別を修正した。

自陣3人の復活床を配置JSONに統一し、コードによる追加生成を廃止した。人物と初期室・復活室・担当床の対応も設定時に検査し、核室への不正な床移設や床の欠落を拒否する。門の回帰検査は各人物の初期室と復活床が属する室を対象とした。

## 未実施・次段階

- R2の実移動・突進の連続当たり判定、砲撃、運搬・装填、敵行動、広場横断、名前登録・カウントダウンを通した一戦。
- 1床単位＝1000整数の移動用座標。R1の位置はセル座標であり、床の接続検査は人物半径や連続衝突を検証していない。
- R3以降の配分・修理・妨害・命令、練習、結果表示、得点、共有、上位10位ランキング。
- iPhone実機のSafari、片手操作、音、発熱・電池・FPS、長時間試遊・連続再戦。
- ランキング接続とサーバー側検証。登録先・game_slugを推測した接続は行っていない。

`docs/plans/current/ACCEPTANCE_TESTS.json` の135件は計画全体の検査仕様。R1の部分検査から個々の受入検査全体の合格へ読み替えず、すべて `not_run` を維持する。採用画像の破損記録も、正常な原本を取得するまで未解決とする。
