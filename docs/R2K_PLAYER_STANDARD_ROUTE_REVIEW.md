# R2k 標準条件の主人公ルートレビュー

## 判定

標準配分、P2/P3無保護、敵AIの干渉を同じ物理試合へ戻した bounded run は成立した。P1は公開操作で実際の床ケースを拾い、4,200更新までに4回以上の配送を行い、P2/P3もケースを運搬した。敵砲撃による自陣外装の損傷も同じ更新列で発生した。

受渡し枠が砲台の待ち列へ直ちに入らない更新では、同陣営のP1へそのケースを通常 `pickup` として提示しない。これにより、P1が受渡し済みケースを拾い直して同じ砲台へ再配送するループを防ぐ。砲台が受け入れ可能な場合の `load`、相手陣営による受渡し床の盗取、AIの自動装填は既存の物理契約を維持する。

## 今回確認した事実

- `createBattle` の標準配分（標準弾3、重量弾2、防護板2、高速杭1）を変更せずに使用した。
- P1以外を保護せず、P2/P3のケース運搬を確認した。
- P1は初期位置から床ケースを拾い、公開 `deliver` を4回以上受け入れた。
- 敵砲撃による自陣外装の損傷を確認した。
- `handoff` の同陣営再取得は提示・実行されず、既存の相手陣営による盗取経路は回帰した。

## 検査の境界

4,200更新の bounded run は、標準一戦の勝利、広場警備の戦術、残りの外装・門・核接触、味方命令、敵30人の復活を完了扱いにしない。結果詳細・得点・ランキング、iPhone実機・試遊も未確認である。次は砲台待ち列の通常運用、味方命令、広場戦術、標準一戦の勝利を分けて確認する。

## 結論

R2kは、R2jの保護fixtureから標準条件へ戻す最初の後続単位であり、主人公の通常配送、味方AI運搬、敵砲撃干渉、受渡し床の同陣営再取得防止を追加した。標準一戦全体の完成や公開可否は、残件として維持する。
