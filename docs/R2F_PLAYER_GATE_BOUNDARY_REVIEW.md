# R2f 主人公の敵城・閉門境界の独立レビュー

対象はPR #40取り込み後の主人公通常操作の小単位である。P1が公開 `direction` / `handle` / `dash` だけで広場警備を撃破して敵城へ越境した後、敵城内の閉じたG1を越えずに停止することを、追加回帰検査と既存の物理境界の読み取りで確認した。明示的な `bridge`、座標越境、門開放、外装破壊、核接触はこの検査へ注入していない。mainへの直接push、マージ、公開承認はこのレビューの範囲外である。

## 発見と確認

|観点|確認内容|結果|
|---|---|---|
|公開入力|補給・砲台受渡し・広場移動は公開 `direction` / `handle`、警備との接触は公開 `dash`、越境後の敵城内移動は held `direction` を使う|確認済み|
|越境後の経路|P1が敵城の `central_corridor` → `respawn` → `corridor_0` まで進み、次の `corridor_1` へは進まない|確認済み|
|閉門境界|敵城のG1を閉じたまま、`pathGates` は空、7門の `openGateIds` は空、外装破壊数は0のまま|確認済み|
|停止の再確認|同じ公開方向を120更新続けてもP1の固定座標が変わらず、入力自体は公開 `direction` として受理される|確認済み|
|fixtureの意味|広場の3防衛者は一接触で倒せる固定fixture、対象外の敵AIは保護fixtureとし、広場戦術・体力バランス・敵AI移動を境界検査から分離|確認済み。通常戦全体の証拠ではない|

## 検査結果と残る境界

今回の追加差分は既存の物理移動・閉門衝突契約を公開入力の経路検査で固定するテストと資料であり、本番コードは変更していない。追加シナリオは1/1通過し、既存の同ファイル2件も通過した。全Node回帰275/275、資料57/57、型検査、Vite製品ビルド、差分空白検査、Quality #175のChromium/WebKit 50/50も通過した。重大な未解決所見はない。

採用配置での運搬・迎撃・砲撃から7部位破壊、広場戦術全体、7門の順次開放、核接触、終局、味方命令、正式結果・得点・ランキング、iPhone実機・試遊はこの単位の合格範囲に含めない。Quality #175は提出差分の自動検査結果であり、実機・試遊の代替ではない。閉門前で止まるfixtureを主人公の通常戦一戦走破の完成証拠へ読み替えず、残件は [公開チェックリスト](RELEASE_CHECKLIST.md) を正とする。
