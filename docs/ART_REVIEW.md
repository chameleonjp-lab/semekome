## 発見した表示上の問題と対応状況

1. **広場の城外観がカメラに追従しない。修正済み、ブラウザ未確認。** 発見時、`src/presentation/battle-renderer.ts` の `drawFortressFacade` は世界座標 `x/y` に `scale` だけを掛け、広場カメラの `cameraX/cameraY` と `top` を反映していなかった。横360pxの中央広場カメラでは敵城の x は約1,300px以上となり画面外だった。renderer担当が `sx/sy` で両城をビューポート座標へ変換してから矩形・7部位・耐久バー・ラベルを描く修正を適用した。
2. **敵の砲台・飛翔ケースが逆向き。修正済み、ブラウザ未確認。** `docs/ART_GENERATION_PROMPTS.json` は `turret` の砲身とケースの先端を右向き指定する。一方、採用配置では敵城正面は左、敵弾の進行も右から左。発見時、`src/presentation/battle-renderer.ts` の敵砲台画像・飛翔ケース、`src/main.ts` の敵陣砲台画像は無反転だった。現在は配置プレビューの敵砲台グループ、Canvasの敵砲台・敵飛翔ケースとも水平方向に反転する。文字・配置座標・プレイヤー操作は反転しない。
3. **迎撃効果が飛翔経路と無関係に帯中央へ出る。修正済み、位置は近似。** 発見時の `drawFlightLanes` は直通/迂回の区別がなく一律中央に描いていた。現在は描画器が前回描画の2飛翔物の経路と進捗を記憶し、同じ経路で消えた2物体の位置の中点へ効果を置く。ブラウザフレーム間に複数tickが進んだ場合は前回位置からの近似であり、物理判定の接触座標ではない。
4. **敵設備が青緑の共通画像だけで所属を区別しにくい。修正済み、ブラウザ未確認。** 敵城の砲台・補給口には赤茶の輪郭・背景アクセントが加わった。Canvasの設備にもチーム色の輪郭を重ね、ゲーム状態は変更しない。
5. **320px幅で戦闘ヘッダーがはみ出す。修正済み、実ブラウザ確認。** 最長の「補給妨害」「通路妨害」を同時表示すると、修正前はヘッダー幅が342.6pxとなり320px画面の本文幅300pxを超えた。`.battle-header { min-width: 0; }` と18pxアイコン・狭い間隔で修正した。Noto Sans JPを使った320×640と360×640の実画面でヘッダー右端はそれぞれ310px/350px、補給予告は幅122.28px内。両名称の実測 `scrollWidth = clientWidth = 40px` で全文が収まることと画像を確認した。

## 確認済みの境界

- `src/presentation/game-art.ts` の画像読込はCanvas描画のキャッシュを使い、欠けた画像には図形フォールバックがある。床のキャッシュは `CastleLayout` オブジェクトをキーとし、`cloneBattle` は `layout` 参照を維持するため通常の1tick毎の床再生成は起きない。
- 敵30人の人数・P1〜P3・核と7門は描画のために新しい状態を生成せず、状態参照・採用配置の左右反転を使う。HTMLの補給選択と荷物枠の文字は画像導入後も保持されている。
- 最新差分に対して `node --test tests/presentation/battle-renderer.test.ts` の4件、`npm run typecheck`、`git diff --check` は通過した。迎撃位置検査で当初失敗した期待座標は、幅360px時の経路左端が `min(43, 360 × .13) = 43` であることを踏まえ修正され、再実行で通過した。
- 別途、実装側の最終検査では Node 219/219、Chromium 12/12、資料57/57、ビルドが通過した。範囲と環境は `ART_IMPLEMENTATION_REPORT.md` を参照する。

## CI後の限定再レビュー

WebKitの小画面レイアウト検査では、実時間カウントダウン中に一時停止画面へ移っていた。失敗画面・開始操作のトレースと、250ms超過で停止する既存 `SessionClock` から、CIの描画負荷が実時間進行へ影響したと判断した。検査側だけを他の戦闘テストと同じ `page.clock.install` / `pauseAt` / `runFor(3100)` に合わせた変更を確認した。5種類の画面サイズ、48px操作、地図、停止導線の確認は維持され、検査末尾で操作説明から戻った際の「再開する」表示も引き続き確認する。ゲーム側の中断判定を緩めていない。制御時計を使った該当ローカル検査は約9.8秒で通過し、WebKit CIの再実行結果は別途確認する。

床の描画は、読込済み画像を最初に12×12pxの小Canvasへ一度だけ縮小し、城内セルへ複製する方式に変更された。同じ画像オブジェクトについて小タイルを共有し、床セル・部屋色・壁線と画像欠損時の図形代替は従来のまま。描画結果は近傍サンプリング相当だが、ブラウザの計測による性能改善値や実機の外観評価はこのレビューでは確定しない。
