# 結果・スコア・ランキングの実装計画 / 第5版

## 必須の結果画面
初期公開の結果画面には、勝敗、スコア、スコア詳細、結果シェア、上位10位ランキング、カメレオンJPの実験場リンクを必ず置く。再戦とホームへ戻る操作も設ける案にする。詳細とランキングは各々内部スクロールでき、主要操作を画面外へ追い出さない。ランキングを初期公開から省略する案は採用しない。
スコア詳細は外装破壊、討伐、経過時間、死亡回数、得点項目を区別する。味方が行った砲撃も含む陣営の成果と、主人公個人の行動を混同しない。復活した同じ敵を倒すたびに無制限に得点を稼ぐことを、勝利より得にしない。

## 未確定の得点式
スコアを表示することは指定だが、計算式は未指定。SCORE_PLAN.jsonへ勝利優先の一案を分離し、承認・試遊前に本番ランキングの固定式としない。
案は「勝利なら100000点」＋max(0, 外装破壊数×1000＋一戦で初めて倒した敵番号数×20＋勝利時だけの残秒×10－主人公の死亡回数×100)。残秒は420秒から進行済みの戦闘時間を引き、0以上の整数秒にする。外装は最大7、討伐加点は最大30番号。復活後の再討伐、復旧後の設備破壊、同じ部位の通知では加点しない。総討伐回数は詳細に示しても得点と分ける。
勝利以外は時間加点なし。引き分け・敗北も結果と詳細を保存するが、途中中止・練習はランキング送信の対象外とする。式・試合条件を変える場合はルール版とスコア版を変更し、旧得点と混ぜない。標準の一設定だけを最初の共通ランキング対象とする案は維持するが、初期公開のランキング表示・接続を必須の完成条件とする。別難易度・別編成の扱いは公開前に決める。

## 実験場との接続
実験場リンクは https://chameleonjp-lab.github.io/chameleonjp_lab/ 。共有側READMEとランキング共通規約を確認した。規約本文: https://github.com/chameleonjp-lab/chameleonjp_lab/blob/main/docs/chameleonjp-lab/11_ranking_integration_standard.md 。接続直前に最新版と実データベースを再確認する。
この更新でSupabaseを変更せず、接続できたとも登録されたとも扱わない。`SCORE_PLAN.json`は式の提案、`RANKING_INTEGRATION_PLAN.json`は接続前のnull設定を記録する。game_id、game_slug、正式なゲームURL、受付処理、取得処理、認証方式、同率順位の返し方は接続先で確定する。URLや作品名から未確認の識別子を生成しない。RANKING_INTEGRATION_PLAN.jsonのnullは未確定値であり、送信可能な設定ではない。
開始記録と結果送信はそれぞれ再送しても一件にする。再送には同じ識別子と内容を使う。名前確定後の開始成立、対象となる終局結果で自動送信し、任意の登録ボタンだけに頼らない。接続側の規約に従って初回・ベスト両方のランキングを扱い、画面ではベスト上位10位を初期表示する案とする。同率順位は返された順位を使い、単に配列番号から順位を捏造しない。10位同率を全員表示するか最大10件かは取得契約で確認する。接続失敗中も結果画面、スコア詳細、再戦、ホーム、シェアを利用できる状態を保つ。
送信状態はidle / submitting / submitted / retryable_failed / permanent_failedを使い、表示の日本語から状態を判定しない。通信時間切れや再送可能失敗では結果・再戦・ホーム・シェアを失わず、同じ結果だけを再送する。取得0件、取得失敗、読込中を区別し、偽のランキングで埋めない。ローカル履歴を世界ランキングと表示しない。
公開前はranking-manifest.json、実装、登録値、配備物を照合する。秘密キーは資料・ブラウザ・ログへ入れない。公開用キーだけでも安全性や不正防止が完了したとはしない。サーバーで入力上限・対象ルール版・同一送信の重複を検査する。ブラウザだけで算出した得点は、再生検証等を別途設けない限り不正耐性を保証しない。

## シェア
結果の名前、勝敗、確定スコア、得点条件、正式URLから共有文を作る。共有機能が使えない場合はコピー、コピーできなければ選択可能な共有文を表示する。共有をキャンセルしても再送・再戦を発生させない。公開URLが未確定の開発画面で架空の公開先へ誘導しない。
実験場を開いたときや結果画面を開き直したときに、開始記録や結果を二重計上しない。図中のサンプル得点とユーザー名を実データへ送らない。
