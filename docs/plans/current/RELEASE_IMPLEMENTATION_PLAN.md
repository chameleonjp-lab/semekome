## 1. 今回の結論と計画の位置づけ

残作業を、下表の**5工程と、その後の公開手順**にまとめる。各工程は原則1本の作業ブランチと1本のDraft PRで提出する。工程内の修正・検査・記録はまとめて進め、門1枚、集計1項目、表示1部品だけで作業を終了しない。

変更をレビューして取り込む依頼をプルリクエスト（PR）と呼ぶ。途中の修正を自動で検査する仕組みを継続的インテグレーション（CI）と呼ぶ。今後は、実装中に関係する短い検査を行い、工程の締めで必要な全体検査を行ってからPRへ送る。

## 4. 工程1：検査の進め方と残件を一度に整理する

### まとめて行う作業

現在のQualityは`push: [main, feat/**]`と`pull_request`の両方を使い、同じ更新へ2回の検査が発生している。PRへの更新を作業枝の基本とし、**作業枝へのpush自動検査を外し、PR更新・main更新・手動実行を残す**案を実装する。mainの検査は取り込み後の整合確認として残す。

同じPRで古い更新だけを取り消す設定を使い、別PR・main・公開作業を誤って取り消さない。変更前に現在の必須チェック名を確認し、そのチェックが通常PRにも資料だけのPRにも完了する構成を保つ。保護設定は変更しない。

検査は「資料と型・ビルド」「短いルール・入力・表示」「一戦全体と長時間」「ブラウザー」「実機」に分ける。現在の`npm test`は全件の入口として保持し、短い検査と長い検査の追加入口を用意する。長い検査の移動先・実行条件・残した確認内容を一覧にする。

同じ標準戦の序盤を何度も進める検査は、共通の走行器や、一度の走行で複数の通過点を確認する方法で重複を減らす。初期条件・無敵設定・期待する境界が異なる検査まで一つにまとめない。以前の不具合を防ぐ確認は残す。

135手順は既存コード・自動検査・実機・試遊のどれで確認するかを結ぶ。各工程が終わる際に証拠を更新し、過去資料を一括で「完了」にしない。古い次工程の案は履歴と明記する。

現在の表示はCanvas/SVGとHTMLを使い、依存物にPhaserはない。初期提案にPhaserがあっても、それだけで全面移行を公開条件へ追加しない。通常戦を進める物理側と共通ルール側は、検証済み境界を維持する。同じ試合へ両方の時計を重ねて進める統合は行わない。公開に必要なのは両系統の全面作り直しではなく、通常戦から必要なルールを一度だけ通すこと。

### 締めの確認と提出

重複を外す変更前後で、一回の更新から何回の検査が始まるか、検査時間、確認内容、必須チェックの完了を記録する。今回測定した値は次のとおり。合計はジョブ開始から完了までで、待機時間を含めない。

|---|---:|---:|---|
|Quality #461 / PR更新 / ブラウザー省略|268秒（4分28秒）|251秒|省略|
|Quality #459 / PR更新 / ブラウザー実行|648秒（10分48秒）|260秒|316秒、導入等は別|

#460と#461は同じ作業枝の同じ更新をpushとPR更新でそれぞれ成功させた。ログには25,000更新の耐久検査約121秒、標準勝利約66秒等もある。長い検査には役割があるため、実行条件を分けて残す。ブラウザー省略だけでは残る待ち時間を解消できない。

短いPR検査は2分以内、資料だけの処理本体は30秒以内をまず測定目標にする。GitHubの待ち時間や環境差があるため保証しない。必要な検査を落として数値だけを達成しない。

工程1は速度と整理をまとめた1 PRにする。暫定値・得点・公開先の判断がまだ返っていなくても、接続値を必要としない工程2・3を止めない。

## 5. 工程2：標準通常戦の戦闘と役割分担を完成させる

### まとめて行う作業

運搬から迎撃・砲撃・修理・妨害・広場突破・7門・核・観戦・終局までを、一つの通常戦として扱う。既存の標準勝利検査を出発点にし、通過点の確認だけを追加して別PRにしない。

8ケースは通常の補給選択から、現物取得・装填・発射・特殊効果・消費・表示まで通す。弾の組合せ64通りの基礎と、分裂・停止・全壊・設備復旧等の追加境界を既存検査へ対応付け、不足を埋める。ケース一つから発射と修理を二重成立させない。

補助員の運搬型・迎撃型・整備型から2人を選び、同じ型2人も選べるようにする。編成画面、型データ、仕事の選択、正式な砲撃・防衛・侵入命令、目標指定、命令取消し、状態表示まで同じ工程に含める。既存の守備・補給復帰と待機指示を生かす。

命令は生存世代と試合へ結び付け、被弾・死亡・停止・再戦で古い予約を破棄する。別室救援や侵入は、見えている情報と正しい室間経路から歩いて行う。閉門・壁・通行権を飛び越えない。仕事の競合、満杯・停止した砲台、届かない目標、主人公死亡後の帰還もまとめて解決する。

敵30人は射手・護衛・運び手・内部兵の仕事、局所警戒、退避、再選択、巡回・広場警備・反攻を同じ一戦へ接続する。敵への防衛優先調整で、主人公が侵入した後に敵が永久に攻められなくなる状態を残さない。各20秒復活と人物番号を保ち、射手を倒した効果・輸送を止めた効果が実際の射撃へ表れることを確認する。

初期状態、乱数、版、受け付けた順番付き入力を保存し、同じ実行条件で終局または所定の通過点まで再生できるようにする。これは調査用の戦闘記録であり、サーバーによる不正得点検証の完成とは別である。

## 6. 工程3：練習・設定・画面・音をまとめて完成させる
