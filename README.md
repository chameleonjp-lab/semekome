# semekome / セメコメ

城同士の砲撃で外装7部位を破り、7つの門を開け、敵陣へ乗り込んで核を攻撃する独自ゲームです。現在は8武器の共通砲撃ルール・敵の判断基盤と、通常戦の開始から勝敗表示、人物接触時の主人公の近接攻撃、主人公側の7部位・7門・核への公開操作境界までを接続しています。正式な結果詳細・スコア・ランキングは未接続です。

表示要素を [素材一覧](docs/VISUAL_ASSET_INVENTORY.md) に整理し、ステージ・人物6種・設備5種・弾8種・床・効果の計22画像を個別素材として実装しました。ホームの「素材図鑑」で全点を確認でき、配置確認・出撃準備・運搬と砲撃の操作確認に反映しています。[制作と実装の記録](docs/ART_IMPLEMENTATION_REPORT.md) に対応箇所と検査範囲をまとめています。

PR #34後の [素材・挙動監査](docs/ART_BEHAVIOR_AUDIT.md) で、越境時の荷物所在と描画の整合を修正しています。確認した範囲と残件は [独立レビュー](docs/ART_BEHAVIOR_REVIEW.md) に記録しています。

現行は第5版。自陣は左、広場が中央、敵陣は右。敵30人は20秒で復活し、主人公は5秒の観戦後に自陣で復活します。画面・広場・スコア・結果・上位10位ランキングを計画へ反映しています。

PR #36で「突進」ボタン・Spaceキー、核への実接触、簡易終局表示、観戦・復活時の入力切替を取り込みました。R2jでは主人公側の7部位・7門・核への公開操作境界を、実際の補給ケースから勝利状態まで接続し、R2kでは標準配分・P2/P3無保護の通常操作を、敵砲撃の干渉を受けながら4回以上の公開配送と味方AIの運搬まで確認しています。R2kは標準一戦の勝利や正式結果画面・ランキングの完成を意味しません。公開までの残対応と確認条件は [公開チェックリスト](docs/RELEASE_CHECKLIST.md) にまとめています。

実装範囲は [進捗](docs/IMPLEMENTATION_PROGRESS.md)、検査の実施範囲は [検査記録](docs/TEST_REPORT.md)、採用した補足案は [実装判断](docs/DESIGN_DECISIONS.md)、主人公側の公開走破境界は [R2jレビュー](docs/R2J_PLAYER_SEVEN_GATES_CORE_REVIEW.md)、標準条件の後続検査は [R2kレビュー](docs/R2K_PLAYER_STANDARD_ROUTE_REVIEW.md) を参照してください。ランキング未接続・実機未検査です。mainへ直接変更せずDraft PRで進めます。

直近の後続検査では、受渡し済みケースを同陣営の通常 `pickup` として再取得できないようにし、砲台の `load` と競合しない状態で、標準条件の主人公操作と味方AIの運搬を同じ試合で確認しています。移動AIや通常戦全体の完成を示すものではありません。

## 配置確認画面

ホームからルール説明を開くか、「配置を確認する」で自陣・広場・敵陣を確認します。地図はドラッグ・矢印キーで見渡せます。「見たい場所」で部屋を選択し、拡大・縮小・全体表示を切り替えられます。カメラを切り替えても人物や世界を再生成しません。

## 通常戦の操作

「通常戦を始める」から名前と補給4種類の配分を入力し、3秒のカウントダウン後に開始します。左のパッドを動きたい方向へずらすと移動（キーボードは矢印またはWASD）。床の弾の近くで右のボタンを押して拾い、通路を通って砲台へ運び、装填します。砲台の操作位置に立っている間だけ自動発射します。左・右の所持枠、次に装填する弾の経路・狙う外装、自車に次に届く2個を確認できます。勝敗表示まで同じ通常戦の状態で進みます。

開始位置の上に弾薬庫A、その隣に砲撃室Aがあります。右上の小地図は現在位置の確認用です。一時停止・画面離脱後は「再開する」で戻ります。「?」で操作説明を開くと戦場も止まります。名前は外部へ送信せず、架空のスコア・順位は表示しません。

敵と同じ広場または城内ルームで接触しているときは「近接攻撃」ボタン、Enter、Xキーで一回の人物損傷を与えます。対象がいないとき、復活保護中、観戦中、停止中は操作できません。コアへの勝利攻撃は近接攻撃ではなく、7門通過後の突進です。

「突進」またはSpaceは押し始めに1回だけ発動し、移動中は現在の方向、停止中は最後の移動方向へ進みます（初期は右）。再使用待ち・観戦・復活保護・停止中は発動しません。全7門を通った後、敵の核そのものへ突進を当てると勝利します。核室への入室や歩行接触だけでは勝利しません。

敵の侵入班も、広場から自陣へ入り、開いた7門を通って自陣の核を突進で狙います。主人公や味方が広場にいる間は敵の入城を止めますが、自陣の内部にいるだけでは広場の通過を止めません。

## 開発と検査

Node.js 24とPython 3が必要です。

```sh
npm ci
npm run dev
npm run check:docs
npm test
npm run build
npx playwright install --with-deps chromium webkit
npm run test:browser
```

`npm run dev` は `http://127.0.0.1:4173` に配置確認画面を起動します。資料検査は通常、検査結果ファイルを書き換えません。GitHub Actionsは同じ検査とビルドを行い、確認用ファイルを成果物に保存します。公開は行いません。

## 次の段階

R2aでは8武器を共通データから動かし、現物の取得・装填、射手の確認、共有発射間隔、迎撃、分裂、外装着弾をルール処理でつなぎました。4役割の敵は仕事の意図を選び、近くの取得・装填・砲台操作だけを実行します。詳しい境界は [共通ルールの接続契約](docs/RULE_ENGINE.md) を参照してください。

共通ルールのR3経路では、補給生成から配送予約・室間移動・待ち列投入までを追加し、予約後に砲台が停止した場合も配送先を再選択します。これは物理操作確認版の固定座標AIや画面導線とは別で、通常戦を通した完成ではありません。
